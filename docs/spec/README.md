# spec/ —— 规范与定义

本目录承接**对项目、某个领域或某类产出生效的规范、规格与机器可读的定义文件**，回答“什么才算合格、合法”。它与 `design/` 的分界是：`spec/` 说的是约束与判定标准，`design/` 说的是我们打算做成什么样；与 `analysis/` 的分界是：进了 `spec/` 的条款已经是定论，仍在权衡的留在 `analysis/`。

## 命名约定

人读的文档用 `<主题-slug>.md`；机器可读的定义文件保留其既有扩展名（如 `hardware-profile.yaml`），因为读取它的工具按扩展名解析。本目录**不按用户名分目录**，路径要稳定，正文由多人共同评审后修改。

## 必备章节与退役

必备章节为适用范围、条款、准入或判定清单、版本。退役时不移动位置，而是在文首标注 `Superseded` 与替代文档路径，因为它的路径常被代码、脚本与其它文档直接引用，移动会让引用集体失效。

## 与其它目录的关系

- 规范是 `design/` 与 `plans/` 必须满足的前提；
- 规范条款的判定依据若来自外部手册或第三方标准，在文中指到 `reference/` 的具体文件；
- 规范本身的制定过程与取舍记录留在 `analysis/`，定型后才以 ADR 或本目录条款落地。
