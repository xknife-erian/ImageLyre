PRODUCT REQUIREMENTS摘要

ImageLyre 是一款面向科研显微图像的跨平台桌面定量分析软件，以 ImageJ 的操作习惯与结果口径为基线，用 .NET 10、AtomUI 与自研插件沙箱重做日常分析工作流。它要解决的不是「再做一个图像查看器」，而是让研究者在不改变既有操作经验的前提下，把导入、校准、选区、测量、复核与导出这条链路做得更快、更稳、更可复现，并且能用 Python、插件与纯 CLI 把重复劳动批量化。

产品边界是「日常定量分析闭环 + 可扩展插件底座 + 可验证的科研输出」：P0 覆盖格式读写、视图、ROI、测量、导出、溯源与纯 CLI 闭环；P1 覆盖颗粒分析、工程文件、Python、插件市场、企业插件、安装部署与团队协作；P2 覆盖配准、共定位、三维与 AI 增强，均以插件或增强功能形式提供。

PRODUCT REQUIREMENTS产品定位

1.1 一句话定义

面向生物显微、荧光、电镜与一般科学定量场景的开源桌面分析平台：ImageJ 用户零迁移成本上手，结果可与 ImageJ 对照，插件与脚本可沙箱并行执行，核心开源、企业插件增值。

1.2 目标与非目标

目标：

  1. 有 ImageJ 经验的研究者十分钟内完成第一次测量，不需要重新学习菜单逻辑。
  2. 同一图像、同一参数在 ImageLyre 与 ImageJ 上得到可对照的结果，差异有明确容差与可引用的验证报告。
  3. 重复分析从手工操作变成脚本与批处理，插件崩溃不拖垮主程序。
  4. Windows、Linux 与 macOS 界面与结果一致，核心功能完全离线可用。
  5. 纯 CLI 模式可在无显示、无交互的环境完成同一分析闭环，供 AI 与外部流水线直接调用。

非目标：

  • 不做显微镜采集控制与硬件联动，采集仍由厂商软件完成。
  • 不做通用图像编辑与平面设计。
  • 不做云端协作与在线项目库；商业授权可采用离线授权码，账号体系不属于首版。
  • 不做医学影像诊断用途。
  • 不兼容 Java 插件与 IJM 宏，不引入 Java 运行时。
  • 主程序不做三维重建、反卷积与 AI 分割，这些能力通过插件提供。

1.3 竞争格局与商业模式

产品优势相对 ImageLyre 的缺口
ImageJ / Fiji生态最大、习惯成熟、免费界面陈旧、单线程、插件全局状态、Java 运行时、批处理弱
QuPath病理全切片与标注强面向病理流程，通用显微定量与 ROI 兼容弱
CellProfiler流水线化批量分析强交互式探索弱，学习曲线陡
商业平台（Imaris、ZEN、NIS-Elements 等）采集与分析一体、售后完善昂贵、绑定硬件、导出与脚本自由度低

差异化落在三点：习惯兼容（操作与结果口径向 ImageJ 对齐）、架构现代（AtomUI 界面、插件沙箱、Python 一等公民、跨平台）、无授权负担（核心以木兰宽松许可证 v2 完全开源，不引入 AGPL 依赖）。核心完全开源，企业插件以商业授权提供，两者共用同一插件市场与沙箱；免费用户不缺核心能力，商业用户为增强功能、批量规模与支持付费。

2.2 核心任务（JTBD）

  1. 拿到一批显微图像时，按熟悉的 ImageJ 流程完成校准、选区与测量，并导出可直接进论文的 CSV。
  2. 同一实验需要重复分析几十上百张图时，用录制脚本或批处理流水线在后台跑完，并给出进度与失败原因。
  3. 厂商格式或新算法出现时，通过插件扩展能力，不必等主程序发版，也不担心插件把软件弄崩。
  4. 复核他人结果时，能看到测量参数、校准来源与软件版本，并用同一份输入复现。
  5. 课题组统一分析口径时，一套配置、一份工程与一份验证报告能在多台机器与多人之间传递。
  6. 当 AI 或外部流水线需要调用时，用纯 CLI 与 JSON 结果完成校准、ROI、测量与导出，不需要模拟桌面操作。

核心分析工作流

典型路径与 ImageJ 对齐：打开图像 → 设校准 → 画选区 → Measure → 看 Results → 保存。批量路径复用同一套能力，不允许出现「只有界面能做、脚本做不了」的分析能力。

PRODUCT REQUIREMENTS产品原则

  1. ImageJ 习惯优先：菜单名称、工具分组、ROI 手势、测量流程与常用快捷键向 ImageJ 靠拢，偏离必须有登记与替代路径。
  2. 结果可对照、可复现：格式、校准、指标与 CSV 以钉死的 ImageJ 基线为基准；每次导出都带溯源，发布前用黄金数据集与验证报告说话。
  3. 预览与定量分离：视图缩放只改变显示，测量与导出只使用数据缩放或原始像素。
  4. 默认离线、网络分级：核心路径零网络请求；市场、更新、遥测与授权属于显式或可关闭的网络功能。
  5. 渐进式复杂度：新手五分钟完成测量，进阶用户再接触录制、脚本、插件与批处理。
  6. 失败可恢复：长任务可取消、插件崩溃不波及主进程、异常有可读原因与可导出的诊断包。

PRODUCT REQUIREMENTS信息架构与核心对象

4.1 界面骨架

主窗口由菜单栏、工具栏、图像视口、可停靠面板区、状态栏与通知区组成。面板区默认提供 Results、ROI Manager、Histogram、Line Profile、Log 与插件管理器，可折叠、可拖拽、可保存布局。每个图像默认以标签页管理，支持拖出为独立窗口（P1）。

  • 菜单栏保留 ImageJ 的八个顶层菜单名：File、Edit、Image、Process、Analyze、Plugins、Window、Help。
  • 工具栏按 ImageJ 分组顺序放置选择、缩放、手形与测量入口；图标可用 AtomUI 风格，顺序与快捷键不变。
  • 状态栏常驻显示坐标、像素值、尺寸、位深、校准单位、缩放比例与内存占用。

4.4 工程文件规格（已拍板）

.lyre 是会话与结果的容器，不替代图像格式。默认引用外部图像路径并记录校验和，用户可选择内嵌图像以便迁移。工程保存视图布局、每个视图的缩放与 LUT、ROI 集与 Z/T 归属、结果表、分析历史、校准覆盖、插件版本与软件版本。

容器为 ZIP64，清单 JSON 记录 schemaVersion 与 minReaderVersion；内嵌图像条目使用 stored 方式并附块索引（偏移、长度、块校验和、位深、通道数），保证按块随机读取与懒加载。未知字段与未知插件状态必须原样保留，再次保存不得丢失。旧版本打开新工程必须提示并阻止静默降级。自动恢复使用增量快照，只保存 ROI、结果与参数，不复制内嵌图像，保留最近两份且总量不超过 512 MB。

4.5 进程边界

路径进程归属说明
标准 TIFF、BigTIFF、PNG、JPG 解码，视口渲染、ROI 编辑、像素探针、同步缩放主进程交互热路径与标准解码，禁止跨进程
厂商格式解码（BioFormats.NET 插件）沙箱进程不可信输入隔离，瓦片回传（ADR-0004、ADR-0005）
测量统计（单 ROI 或小选区）主进程或沙箱任务就地执行，不阻塞交互
颗粒分析、栈投影、大选区统计沙箱进程共享缓冲输入，崩溃隔离，符合 ADR-0004
批处理、Python、重计算插件、AI 推理沙箱进程可取消、可进度、崩溃隔离

插件通过宿主发放的只读平面/瓦片句柄与写时复制租约访问像素，底层走只读内存映射或共享内存，Socket 只传控制消息；插件与主进程之间不存在共享可变状态。该模型已由 ADR-0004 定稿，基线升至 1.4。主进程内插件限于不加载第三方代码的内核测量路径；六个槽位之外不新增 Renderer 槽位，三维能力由 Operator 产出体数据并配独立视图实现。

PRODUCT REQUIREMENTS兼容性与精度规范

6.1 基准环境

测量基线钉死为 ImageJ 1.54f 官方发行版（Java 8，Windows 10 22H2 基准机），Fiji 只用于插件盘点，不作为测量基线。版本号、安装包 SHA-256、测量选项模板与导出的基准 CSV 一并作为 fixture 入库，基线升级必须走 ADR 并重跑验证报告。所有对照在固定机器、固定线程数与固定显示缩放下进行，环境写入报告。

6.2 格式与元数据

ImageJ TIFF 的空间校准、帧间隔、通道名与 LUT 必须保留；BigTIFF 与多页 TIFF 的帧顺序与 ImageJ 一致；厂商格式按 IO-012 的字段矩阵校验，必读字段缺失时阻断测量并提示，不得静默补默认值。

6.3 ROI 兼容

.roi 与 .zip 双向可读写，六类选区的坐标、类型与名称导出后不丢失；ImageJ 打开 ImageLyre 导出的 ROI 不报错，反向保持形状与位置；多 ROI 的 zip 按 ImageJ 命名习惯保存。

6.4 测量与 CSV

测量选项基线按附录 B.1 逐项定义：小数位 3、科学计数法关闭、NaN 空单元开启、Limit to threshold 关闭、Invert Y 关闭、Black background 关闭；Results 与 CSV 的列名与顺序逐项固定。标准差用样本标准差（n−1），NaN 像素不计入统计且 N 列记录有效像素数，浮点用双精度累加。自动阈值固定 256 桶，像素值大于或等于阈值判为前景，阈值向下取整到桶边界。

6.5 容差与判定

类别内容判定
A 类二值掩膜、像素计数掩膜坐标集合哈希逐图完全一致
B 类面积、均值、标准差、最小、最大、积分密度abs(a−b) ≤ max(abs_tol, 1e-6 × abs(b))；abs_tol：面积 0，最小与最大 0，均值、标准差、积分密度为 1e-9 × (max−min)
C 类周长、Feret、圆度周长差 ≤ max(1 像素, 轮廓周长 1%)；Feret 差 ≤ 1 像素；圆度差 ≤ 0.01
D 类中位数整数灰阶逐值一致；浮点按 B 类容差
E 类位置与角度：X、Y、MinFeret、FeretAngleX、Y、MinFeret 差 ≤ 1 像素；FeretAngle 差 ≤ 0.1°
F 类偏度、峰度总体矩公式，差 ≤ max(1e-3, 1e-6 × abs(b))
自动阈值Otsu 等掩膜像素差异 ≤ 0.01%，且阈值整数化后与基准相同

与 ImageJ 冲突时默认以 ImageJ 为准；若判定 ImageJ 侧错误，须由课题负责人与成像平台技术员会签勘误表并纳入验证报告。

6.6 黄金数据集与验证报告

黄金数据集按 VAL-002 维护，验证报告按 VAL-003 生成，发布门禁引用报告链接。参考工作流按 VAL-004 覆盖颗粒计数、时间序列强度与比例成像；共定位按 MEAS-008 在 P2 单独验证。

6.7 文本序列化契约

CSV 默认 UTF-8 无 BOM、逗号分隔、LF 换行、小数点为 . 且不随 locale 变化；含逗号、引号或换行的字段用双引号包裹并转义内部引号；NaN 与无穷写为空值；面向 Excel 的 BOM 开关单独提供，不改变解析后的值。工程清单 JSON 与 sidecar 固定 UTF-8 无 BOM。暴露与持久化的路径统一 NFC，比较前先归一化；跨平台一致性比较解析后的数值，不比较字节。

  • 长任务显示进度与取消，超过两秒必须有反馈。
  • 破坏性操作需确认；可撤销操作优先提供撤销。
  • 错误提示包含发生了什么、可能原因、下一步，并提供一键复制诊断信息。

7.3 大图与多视图

超过视口四倍的图像分块渲染与缓存；缩放以光标为中心；拖拽平移不触发重新解码；多视图同步以主视图为基准。

7.4 可访问性

按 ACC-001 至 ACC-005 执行，键盘路径与鼠标手势并存，冲突时以交互设计文档登记等价路径。

8.5 平台与分发

支持 Windows 10 1809+、macOS 12+（Intel 与 Apple Silicon）、Ubuntu 22.04+（x64 与 arm64）。三平台均采用 self-contained 分发，随安装包自带 .NET 10 运行时，不要求机器预装；安装在包含 Python 与 BioFormats.NET 的前提下总量不超过 2.0 GB。Windows 使用 Authenticode 签名，macOS 使用 Developer ID 签名、公证与 hardened runtime，并逐条列出子进程、原生插件与 Python 所需 entitlements；Linux 发布 SHA-256 清单与签名。未签名包仅限内部测试，不得对外分发。

NativeAOT 仅用于主启动器与 CLI，插件宿主与 Python 运行时使用 JIT；该边界需在架构基线中以 ADR 记录。核心以木兰宽松许可证 v2 开源，官方二进制所含 AtomUI 商业授权由项目实体持有并说明再分发边界；第三方自行构建需自备授权。
