## 1 范围与判据

| 侧 | 文档 |
| :--- | :--- |
| 产品 | `requirements/product-requirements.md`（4.1）、`requirements/core-1.0-boundary.md`（0.5）、`requirements/measurement-baseline.md`、`plans/PM-PLAN-0002-m1-vertical-slice.md`（1.1）、`m1/Core-1.0-acceptance-matrix.xlsx` |

判据只有三条：15 个 CORE 的验收语言在架构文档里有没有承接；四件产品内核有没有被反向收窄；迁移与可访问性的承诺有没有落空。

## 2 结论

15 个 CORE 全部能在架构文档里找到承接，没有发现产品承诺被取消。需要收口的是口径，不是范围：

- **会直接影响验收的 3 处**：技术内核条数（PRD 五样，边界与 ADR 七项）、CORE-12 里的「市场」与 7.1 的插件市场冲突、CORE-15 与 §4.6 的可访问性承诺不一致；
- **其余 6 处**：共享契约项的归属、边界正文的「这五样」、矩阵的过期版本号、用户习惯与布局方案、CORE-04 的 `.zip` 口径、200% 缩放与高 DPI 的口径；
- **1 个流程事项**：`dev` 与 `develop` 两条线并存，产品文档已在 `dev` 上走到 4.1，`develop` 停在 4.0。
