# reviews/ —— 评审与专家辩论

本目录承接**设计、方案与交付物的评审记录、专家辩论与裁决依据**，回答“谁在什么证据下赞成或反对、推荐顺序如何形成”。它与 `analyses/` 的分界是：分析只负责把事实与候选方案摆清楚，评审记录的是多方在同一份材料上的独立立场、交叉质询与分歧收敛；评审结论一旦拍板，应升级为 `docs/adr/` 的决策或 `docs/design/` 的现行设计，本目录不承担最终决策的正文。

## 落点与命名

按用户名分一层目录，文件名为 `<YYYY-MM-DD>_<主题-slug>.md`；同一专题的多轮评审可在用户名下加一层主题子目录，只分一层。评审对象是某份设计或方案时，正文必须写出被评审文件的完整路径与版本。

## 必备章节

评审对象与版本、评审席位与专长、评审方法与轮次、证据与评分、共识与分歧、推荐列表、否决条件与遗留问题；每条结论都要能回溯到被评审文件的章节、代码位置或实测输出。

## 与其他目录的分界

- `analyses/` 回答“事实是什么、有哪些候选”，`reviews/` 回答“多方如何评价这些候选”；
- `adr/` 与 `design/` 承接拍板后的结论，`reviews/` 只保留形成结论的过程与异议；
- `daily/` 记录当天做了什么，`reviews/` 是一次可独立检索的评审事件。
