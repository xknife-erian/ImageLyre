### 2. 架构决策（`a328d83`、`7a4c8ab`、`8d118c9`、`63cc548`、`81488f3`、`ef66ff7`、`8316e1f`、`f5c7d36`）

`docs/adr/lukan/ADR-0001-插件机制架构基线.md` 从 0.1 演进到 0.9，共确认九项主决策：

1. cangming 只作插件机制基座，不作应用内核；Shell 的消费型契约没有实现，产品能力由 Lyre 自己的平台插件承载。
2. “一切皆为插件”收敛为三条可验收判定：机制零领域名词、空壳即产品、一能力包一改动。
3. 四种单元 Plugin / Module / Feature / Contract；契约属于架构，插件之间零 ProjectReference；Driver 保留在基线分类但不实现。
4. 分层 L0–L6，机制层与图像内核分离；数据模型留契约层，测量、编解码、算子以官方必装插件提供。
5. 插件治理作为产品自有层，分 G1–G5；G1 即 M1，只用 cangming v1 能力。
6. 契约拆两份：`ImageLyre.Contracts`（界面无关）与 `ImageLyre.Shell.Contracts`（界面相关）；新增 `ImageLyre.Domains` 承载领域对象与纯算法，方向固定为 Shell.Contracts → Contracts → Domains，M1 建空工程并附 README。
7. App 只负责启动、启动参数、启动画面与欢迎界面、编排；主窗体由壳插件在 `Build()` 中产出（对齐 Mercury 的 `MainWindowFactory` 与 `WorkbenchModule`）。
8. 单入口双宿主：同一可执行既启桌面界面也提供 CLI，共用 Bootstrap 与插件集，Feature 在无 UI 模式扫描期过滤；M1 命令为 `--version`、`--plugins`、`--help`。
9. 多语言运行期切换，本地化归宿主基础设施（`ImageLyre.Localization`），壳与插件只注册资源源；三端同构，平台差异只落在基础设施适配层。

另加每个工程必须带 README 的硬约定（§2.9），并同步基线到 2.2：术语改“能力域”、规则 2 按插件类别拆分、新增 Platform 能力域、编解码/算子/测量改称官方必装插件、登记双宿主、多语言与三端同构。
