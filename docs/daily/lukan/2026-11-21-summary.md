## 遗留与说明

**本轮踩过的六个坑，都值得记住：**

1. **新增插件工程必须加 `App` 的工程引用**，否则 dll 不进输出目录、前缀扫描看不到它。空态功能与 Busy 模块各中一次，表现为"插件数没变"。
2. **并行 agent 时不能用 `git add -A`**，会把别人暂存的文件卷进自己的提交。已用 `reset --soft` 拆开。
3. **`Contracts` 不能引 `UI.Contracts`**，撞了两次：一次想把 `SlotDiagnostics` 挂到 `IPluginCenter`，一次想在 `PluginCenterModule` 里调 `ISlotRegistry.Detach`。判断落点看依赖方向，不看"逻辑上跟谁近"。
4. **`Avalonia.Headless` 单独用拿不到帧**，必须同时 `UseSkia()` 且 `UseHeadlessDrawing = false`，还要 `Dispatcher.UIThread.RunJobs()`；`Avalonia.Headless.XUnit` 要 xunit v3，与本仓的 2.9.3 冲突。
5. **`CompleteRegistration()` 会永久置 closed**，之后运行期启停产生的附着会被记 `AttachedAfterClose`，插件中心刷新一次就会变吵。
6. **`SlotHost` 里按 `Snapshot()` 判预留是死逻辑**，`IsVisible = Content is not null` 已覆盖；ponytail 审查指出后已删。

**一个方法论上的收获**：架构师该产出的是机制（位置谁开、怎么命名、父亡怎么收），不是位置清单。把未来插件的落点预先枚举成九个位置，等于替别人决定他们能往哪塞东西——这条被业主当场纠正，已写进 `DESIGN-0005` §12。
