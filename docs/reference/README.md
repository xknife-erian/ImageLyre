# reference/ —— 外部参考资料与定稿存档

本目录承接两类内容，二者的共同点是「只读、按原样保留、路径要稳」：**来自外部的参考资料与可查阅的事实清单**，回答“原文是怎么说的”，例如厂商设备手册、第三方协议文档、芯片寄存器表、标准原文；以及**本项目的定稿设计存档**，回答“已经定稿的那一版长什么样”，例如外观竞标原型与取值基线。它与其它目录最大的差别是：这里存放的**不是现行结论**，因此表格与正文里的说法以来源原文或定稿原件为准，我们的解释与取舍放进 `analyses/`，现行设计与决策放进 `design/` 与 `adr/`。

## 命名与存放

外部资料与定稿存档都**保留原文件名不改名**（如 `IDS830ABS低压直流伺服用户手册V1.0.docx`），因为文件名是来源方的标识或定稿时的既有编号，改名会让别人对不上号；项目自建的查阅清单或摘录用 `<主题-slug>.md`。定稿存档按 `<日期>-<主题-slug>/` 建主题子目录，内部保留原路径结构。本目录**不按用户名分目录**，属于项目共有。

## 必备章节（项目自建文档）

来源与版本、适用范围、条目正文或索引；完成判据是每条事实都能对回原始出处（手册页、协议章节）。外部原件本身不要求改写结构，但应在本目录的自建清单里登记来源、版本与适用范围。
