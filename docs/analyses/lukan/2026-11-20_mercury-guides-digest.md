# Mercury 指南全集阅读台账

## 1 为什么要读

Mercury 的 `docs/guide` 是这套插件体系的一手说明书：它写的不是理念，而是"某件事正确做法长什么样、错了会怎样、怎么验证"。本仓直接用同一套内核（PicoPlugins）与同一套槽位模型，因此这些指南对我们不是参考读物，是操作规程。

## 3 已经能落地的结论（先记，勿丢）

1. **契约交出方式**：指南用 `protected override TModule Module => _service;`，`Build` 只在需要按参数产实例时覆盖。本仓的六个模块已开始从 `Build()` 迁到 `Module` 属性（`BusyModule`、`CommandsModule` 已改）。
2. **没有依赖就不写上下文**：`BasePicoModule<T>` 的默认 `BaseModuleContext` 够用，空上下文类属于噪音。
3. **依赖先声明再取用**：`DeclareDependencies` 里只写 `Require`/`Optional`/`After`，运行期从上下文 `Use<T>()` 取。
4. **目录白名单**：根目录只放身份文件（入口、上下文、偏好、错误、csproj），实现全进 `Internal/`。

## 6 23-标识体系 读后记录（2026-11-20）

**语义确认**。OwnerId 是类型名，用于权限与诊断归组；OwnerInstance 是运行期实例标识，只用于释放与 Detach，不落库。本仓 SlotAttachmentEntry 的两个字段与之一致，此前担心的"混用会让停用即撤失效"不成立，无需改结构。

**三条可直接采信的规定**：

1. 只有 SlotName，没有 SlotKey；完整的三段式是 <区域>[.<用途>][.<方位>]，例如 Driver.Balance.XiPing.Debugger。
2. 声明方、附着方、宿主三处必须逐字一致，不一致分别表现为：声明重名抛异常、附着进 UnresolvedSlot、面板空白。
3. CommandName 用动宾短语、英文、Feature 内唯一；中文或缺失会变成灰显加装配问题。

**本仓的两处偏离**：

- 槽位名现在是 ImageLyre.Menu、ImageLyre.Content、ImageLyre.StatusBar，是"产品前缀 + 单段"，不是指南的"区域 + 用途 + 方位"。它自洽且三处一致，但与我们自己的 WorkbenchSlots 契约放在 WorkbenchSlots 类里这件事叠加后，改名成本低、收益也只是与上游同构。结论：记入待办，不在 A 到 E 的范围内改。
- 附件形态矩阵我们只允许五类且已在 AttachCore 里校验，与指南一致，无需调整。

**一条要补的能力**：指南提到自检窗口按槽位名列出附件与来源，我们只有 Snapshot() 与诊断列表，没有可视化的槽位图。它属于 D 批之后的诊断界面，记入待办。
