## 问题陈述

在多人并行产出的前提下，需要确定 `docs/` 的目录结构与文件命名约定，使新增文档既不与他人重名、也不需要跨人协调序号，同时保证引用可被无歧义地解析。

## 证据

- 现状观察：`docs/` 下已建立 `adr`, `analyses`, `daily`, `design`, `plans` 五个类型目录，说明体裁维度已经先行确定。
- 现状观察：`docs/README.md` 描述的目录表与实际存在的目录不一致（其中提到的 `definitions/` 与 `archive/` 并不存在），说明文档结构变更后缺少同步登记环节。
- 历史样本：`docs/daily/` 中曾同时存在 `<YYYY-MM-DD>-summary.md` 与 `<YYYY-MM-DD>_<主题>_<要点>.md` 两种命名，说明同一目录内允许多种命名范式，但需要在 README 中显式登记。
- 反证：只要编号范围是全局的，任何一次并行起号都需要沟通，因此“靠约定避免撞号”不能替代结构性消解。

## 候选方案对比

| 方案 | 冲突消解 | 引用清晰度 | 迁移成本 | 综合评价 |
| :--- | :--- | :--- | :--- | :--- |
| 全平铺 + 全局唯一序号 | 无消解，需人工协调 | 高（编号短） | 无 | 人数增长后不可持续 |
| 平铺 + 用户名前缀文件名 | 完全消解 | 中（文件名偏长） | 低 | 依赖人工维持前缀 |
| 两级目录：类型 / 用户 | 完全消解 | 中（需写全路径） | 低 | 归属与体裁同时可读 |
| 一级目录：仅按用户 | 完全消解 | 低（体裁靠猜） | 中 | 与现有 5 目录冲突 |

## 结论

采用两级目录结构，即 `docs/<类型目录>/<用户名>/<文件名>`，其中序号在用户目录内独立自增、引用时必须写出完整路径；该结论已升级为决策记录，落在 `docs/adr/lukan/ADR-0001-docs-per-user-layout.md`。
