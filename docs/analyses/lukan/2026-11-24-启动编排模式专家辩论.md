## 1 结论

五席一致推荐 **D（Generic Host + Host/Presentation 两阶段 + 类型化 Step Pipeline + 嵌套 Plan）**，没有一席给出无条件支持；所有支持都附带工程登记、失败语义、退出等待、报告契约或测试条件。C（Generic Host + 责任链）是唯一被接受的退路，B（每步 HostedService）只允许承载机制服务，A（方法抽取）只允许作为迁移前的行为冻结，不构成终态。

增长前提改变的不是排序，而是复杂度的权重：A、B、C 的边际成本随启动项数量线性增长，D 的一次性工程与类型成本被摊薄；因此 D 的优势从“结构更干净”变成“增长时不需要重写编排”。五席在增长复核中全部选择嵌套 Plan，没有一席选择单一扁平 Plan 或运行期注册表。

## 4 共识

1. **Bootstrap 必须 UI-free**：五席一致；Avalonia 控件、`Window`、`SlotManager` 不得进入 Bootstrap 的公开签名或引用闭包。
2. **启动拆两阶段**：Host 阶段不构造依赖插件产物的控件；Presentation 阶段在 Avalonia 消息循环启动后执行；欢迎窗是 Host 阶段前的宿主入口例外。
3. **插件失败是 `Degraded`**：cangming 的构造失败、启动异常、返回 `false`、硬依赖缺失都折叠为 `Failed`/`BrokenPlugin`，应用继续可用；Step 不得把插件失败伪装成异常回滚。
4. **Plan 与报告必须可枚举**：顺序以数据表达，不靠方法体或 DI 注册顺序；报告至少含 Id、组、阶段、结果、耗时、异常类型与回滚标记。
5. **关停必须可等待**：现有 `_ = StopAsync()` 丢弃任务、`WaitAsync` 只放弃等待，两项都必须在迁移中修掉；`CompositionGate` 的“停止先于开始”与并发测试不能被 Pipeline 状态直接替代。
6. **测试脚手架不入 Plan**：冒烟钩子是环境变量驱动的宿主级测试回调，不能变成产品启动语义；其 stderr 串与退出码仍需保留到真实 UI 测试接替。

## 5 分歧与裁决

| 分歧 | 各方立场 | 裁决 |
| :--- | :--- | :--- |
| 是否新建第二工程 | E1 必须建并登记，否则否决；E2 无第二消费者可放 App/Startup；E3 两阶段不等于两工程；E4 第二程序集只是被藏起，需要两个 Context；E5 成本真实，但“无第二宿主”不反证 D | 建 `ImageLyre.Presentation.Desktop`，作为 L5；App 只留入口；Bootstrap 不引用它 |
| 新工程命名 | E1 反对 `Host.Desktop`，因 §2 的“宿主”专指 `IHost`；E2/E3 可接受 `Presentation.Desktop` | 用 `ImageLyre.Presentation.Desktop`，不用 `Host.Desktop` |
| Gate 去留 | E2 坚持删、改由 `ApplicationStopping` 承担；E3/E4/E5 要求保留幂等语义与并发测试；E1 下移为单一幂等入口 | 保留 `ExitArbiter` 的 `TryStop` 先于 `TryBegin` 语义与 64 并发测试；P3 只删重复读取 |
| P1/P2 顺序 | E1 要求 P2 与 P3 类型引入合并，避免二次重写；E3 反对 P1 先落 HostedService 再改 Step；E5 要求 P2 即有顺序断言 | P1 直接落 Step 类型与 HostPlan，不设 HostedService 过渡；P2 建 Presentation.Desktop 并落 PresentationPlan；P3 补回滚、报告、增长压测 |
| 固定机制序 | E3 认为七个机制动作不可拆；E2/E4/E5 认为外层可 Plan 化 | 插件启动压成一个复合 Step，内部七动作顺序固定；外层可排序 |
| 失败终态 | E2 快速失败；E3 Host 快速失败、Presentation 回到“插件运行、无 UI”；E4 桌面停在失败界面；E5 不快速退出并记 `Leaked` | Host 阶段快速失败；Presentation 失败回到“插件运行、无 UI”，桌面显示失败界面，报告含 StepId |
| 回滚粒度 | E1/E5 按 Step 逆序；E3/E4 按资源补偿；E5 要求 `Leaked` 记录 | 只回滚已完成且持资源的 Step，逆序执行；不可逆步骤显式标 `NonReversible` 并记 `Leaked` |

## 6 推荐列表

| 排名 | 模式 | 裁决 | 条件 |
| :--- | :--- | :--- | :--- |
| 1 | D / M10：Generic Host + 两阶段 + 泛型 Step Pipeline + 嵌套 Plan | 主方案 | 十项必备条件见 `DESIGN-0002` §10.2 |
| 2 | C / M3：Generic Host + 责任链 | 退路 | 启动项长期 ≤15、团队不接受泛型 Step；仍须建 Presentation.Desktop |
| 3 | B / M2：Generic Host + 每步 HostedService | 仅机制服务 | 无回滚需求；不作为产品启动项模型 |
| 4 | A / M1：方法抽取 | 仅过渡 | 行为冻结用；不以 App 行数作为完成判据 |
| 5 | M5/M6/M7/M8/M9 | 不推荐为主模型 | M9 仅可在固定组内做可选声明，不得决定顺序 |

主方案的十项必备条件：一个 `IHost` 与单一等待点；HostPlan/PresentationPlan/StopPlan 三份；Step 六项成员；`StepOutcome` 四态含 `Degraded`；`StartupReport` 按组聚合；嵌套 Plan 固定两层、叶组 5–9 项；插件启动压成一个复合 Step；`ExitArbiter` 保留幂等与并发测试；Bootstrap 引用闭包无 Avalonia；App 只做入口。

## 7 退化风险与早期信号

| 风险 | 早期信号 | 处置 |
| :--- | :--- | :--- |
| Plan 退回过程式 | Plan 内出现几十条 `Add(new XStep())`、`if`、`try/catch`、`Task.Delay`；新增项改动超过两个文件或 40 行 | 新增项只允许改所属组一个文件；组内超过 9 项即拆组 |
| Context 变成服务定位器 | Step 靠读取前一步写入 Context 的可变字段传值；`BootstrapContext` 出现大量可写属性 | Context 只读；跨步骤依赖以构造参数或 `GetRequired<T>` 获取，缺失报 StepId |
| 顺序退化为注册顺序 | 顺序测试改为断言日志或源码；Plan 不再是唯一真源 | CI 断言 Plan 的 Id 序列；禁止全局 `Order` 与 DI 扫描排序 |
| 组名退化为垃圾桶 | 出现 `Common`、`Misc`、`Other` 组；单组超过 9 项 | 组名按职责命名；新组须设计评审 |
| UI 偷渡回 Host | Host 组出现 `Dispatcher.UIThread`、`Window`、`Control` | verify 增加 Bootstrap 引用闭包检查；Host 组禁 UI 类型 |
