# 文档 HTML 化

HTML 是 Markdown 的阅读视图，不是第二份正文。它解决的是“长文难导航、台账难筛选、评审要投屏或打印”，不解决“内容要不要改”。

## 何时使用

- 分析、设计、指南、规范类文档达到约 150 行以上，或问题/条款/步骤达到 15 条以上；
- 需要在评审会上投屏、打印成 PDF，或发给不读 Markdown 的同事；
- 文档含两张以上流程图、时序图、状态图，或需要按级别、模块筛选的台账。

不适用：短文档（Markdown 足够）、ADR（靠 git diff 评审）、daily（按天归档、无需导航）、内容还会高频改动且没人负责重新生成的文档、含密钥或客户隐私的文档（HTML 会被随手转发）。

## 输入契约

- 体裁限定为分析类、`design/`、`guide/`、`spec/` 四类；`adr/`、`daily/`、`plans/`、`reference/` 不生成 HTML。分析类目录在多数仓叫 `analyses/`、少数仓仍叫 `analysis/`，以目标仓 `docs/README.md` 的登记与既有目录为准，不要另造第三种写法；落到具体仓库时只替换体裁目录与归档路径，版式、模板与 QA 不变。
- Markdown 必须有标题、日期与适用范围；分析类还要有编号台账，列固定为 `编号 | 问题 | 证据 | 后果`，P1 与 P2 分表；没有编号时先在 Markdown 里补 `P1-1` 这类编号并回写，再生成 HTML，禁止只在 HTML 里编号。
- 图的 Mermaid 源留在 Markdown 中；HTML 只负责渲染，不新增图。
- 代码引用统一写成 `文件:行号`，文件路径相对仓库根、行号对应当前工作区；不允许写“大概在某个文件里”这种无法核对的引用。
- 文档里的数字（条目数、问题数、版本号、行号）在 Markdown 与 HTML 中必须逐一对齐。

## 输出契约

- 位置：与 Markdown 同目录、同文件名换扩展名，例如 `docs/analyses/lukan/2026-11-16_x.md` 对应 `docs/analyses/lukan/2026-11-16_x.html`；不另建 `assets/` 或 `reports/` 目录。历史文档已经放在 `assets/` 或独立文件夹中的不强制迁移，新产出按本约定执行。
- 形态：默认单文件，CSS 与交互脚本内联；仅 Mermaid 允许从 CDN 加载。
- 资源档在文档开头声明，二选一：`web`（默认）让 Mermaid 走 CDN、四级回退，断网时图退化为源码文本并给出提示；`offline` 把图预渲染为内联 SVG，不依赖网络，适合现场演示与对外发送。页脚写明 `资源档：web`（或 `offline`），便于读者判断断网时的预期。
- `<head>` 写入 `generator`（本技能名与版本）、`source`（Markdown 路径）、`date`；页脚重复同样信息并写明“由 Markdown 生成，勿直接编辑”。
- Markdown 头部表补一行 `| 渲染版 | [HTML](<同名>.html) |`，形成双向可查。
- Markdown 与 HTML 同一次提交，HTML 随项目入库、不写入 `.gitignore`；Markdown 变更后必须重新生成 HTML，禁止只改 HTML。
- 表格列宽必须在生成时按表头与单元格内容估算，输出 `<colgroup>` 且各列宽度合计 100%，配合 `table-layout:fixed` 与单元格内换行；不得依赖浏览器 auto 布局或平均分配，否则长代码与长说明会把首列挤成一条。

## 视觉方向（A+C）

全站统一为“仪器面板 + 图纸框”：暖纸底 `#F2EEE4`、墨线 `#151515`、等宽小标签、顶部铭牌、横向目录条、封面图框、章节幽灵编号 `01/02`、问题孔位图、`FIG. 0N` 图注。不要另起配色或版式；完整令牌、组件与反例见 `references/layout.md`。

四个必须出现的签名元素：铭牌（DOC / REV / PAGE）、目录条（编号 + 章节）、孔位图（分析类）、图框角标与 FIG 编号。缺少任一，视觉就不成体系。

章节多时不要硬塞：≤12 章单行铺开；超过 12 章或放不下时，目录条横向滚动，右侧出现“目录 ▾”面板（三列，窄屏一列），当前章自动滚入视野。

## 版式骨架

通用结构固定为：铭牌 → 目录条 → 封面区（图框、标题、规格行、孔位图与读数、徽章）→ 正文 → 页脚。正文按体裁取骨架：

| 体裁 | 章节顺序 | 必备块 |
| :--- | :--- | :--- |
| analyses | 摘要 → 背景/范围 → 业务或问题主线 → 问题台账 → 方案对比 → 结论与遗留 | 可筛选台账、编号锚点、结论卡片 |
| design | 版本表 → 约束 → 结构设计 → 接口契约 → 边界情况 → 变更记录 | 版本表、契约表、结构图 |
| guide | 适用对象 → 前置条件 → 步骤 → 常见问题 → 相关文件 | 编号步骤、可跳转目录、代码块 |
| spec | 适用范围 → 条款 → 判定清单 → 版本 | 条款编号、可勾选清单、锚点 |

台账区固定五列：`编号 / 级别 / 模块 / 问题 / 后果`；证据放在点击行后展开的详情区，不塞进主表，否则一行会高到无法扫读。

## 设计令牌

颜色、字号、间距、组件与打印规则见 `references/layout.md`，生成时直接复用，不要另起一套配色。硬性约束：使用系统字体，不内嵌字体文件，不引用远程图片；正文 15.5px、行高 1.8、纸张宽度不超过 1180px；纸张 `#F2EEE4`、墨色 `#151515`、强调橙 `#C2410C`、P1 `#C92A2A`、P2 `#C77C02`。禁止圆角卡片、投影与蓝紫渐变。

## 生成步骤

1. 读 Markdown，确认体裁、章节顺序与台账编号；缺编号先补 Markdown。
2. 复制 `templates/review.html` 到目标路径，替换 `{{TITLE}}`、`{{项目名}}`、`{{KICKER}}`、`{{LEDE}}`、`{{DATE}}`、`{{SCOPE}}`、`{{META}}`、`{{SOURCE}}`、`{{BADGES}}`、`{{NAV}}`、`{{SECTIONS}}`、`{{FOOTER_NOTE}}`、`{{DOC_ID}}`、`{{REV}}`、`{{SPECROW}}`、`{{OVERVIEW}}`、`{{ASSET_PROFILE}}`；`{{项目名}}` 取页脚铭牌上的项目名（短横线分隔的前缀或中文简称，按目标仓惯例），分析类再把 `templates/findings.html`（片段，不是独立页面）整块粘进 `{{SECTIONS}}`，替换计数与模块筛选按钮。
3. 正文按 Markdown 顺序搬运，不增删结论、不改数字；遇到无法搬运的内容（如表格过宽），改排版而不是删信息。每张表在搬运时按表头与单元格内容估算列宽并生成 `<colgroup>`：短列给最小可读宽度，长说明列取剩余，代码标识符允许 `overflow-wrap:break-word` 在必要时换行；较长代码（约 24 字符以上）在命名空间点与路径斜杠后插入 `<wbr>`，优先在语义边界换行，短版本号与方法调用保持原样，不得用等宽或让浏览器 auto 分配。
4. 台账按“一行主记录 + 一行详情”生成：主记录给 `data-id`（编号小写，如 `p1-1`）、`data-sev`、`data-mod`；详情记录用 `data-for` 指向同一个编号，内部放证据与修复方向。
5. 图放进 `<pre class="mermaid">`；`offline` 档改为内联 `<svg>`，并在图下保留一句图注。
6. 写页脚与元数据，回填 Markdown 的“渲染版”链接。
7. 跑「QA 清单」（第 8 节）全部通过再交付。

## 交互与可访问性

- 目录：滚动高亮当前章节；窄屏折叠为顶部横向导航；锚点跳转后标题不被固定栏遮挡。
- 台账：级别与模块筛选、关键词搜索、展开与收起全部、每条独立锚点；搜索必须覆盖详情里的文件名与行号，不能只搜标题。
- 代码引用：点击复制 `文件:行号`；`file://` 下剪贴板 API 不可用时降级为可手动选择的文本框。
- 键盘与语义：筛选与展开可用 Tab 到达、Enter 触发；表格有表头；颜色不是唯一信息载体（徽章带文字）。
- 图：页面内按宽度缩放，保证整张图可见；点击图框打开原尺寸浮层，可横向滚动，`Esc` 或点击空白关闭。
- 打印：A4 分页，隐藏侧栏与工具条，强制展开全部证据，卡片不跨页断开。

## 反模式

1. 直接改 HTML 不改 Markdown：下一次生成即丢失，且两份正文开始互相矛盾。
2. 内嵌 base64 字体或大图：单文件从 100KB 涨到几 MB，打开明显变慢。
3. 内联 Mermaid 却不做失败降级：脚本一报错，整页只剩空白。
4. 用 `overflow: hidden` 包住带 sticky 表头的表格：表头永远不粘。
5. 搜索只匹配标题，不匹配证据：用户搜文件名时什么都搜不到。
6. 表格不生成 `<colgroup>`、靠 `table-layout:auto` 或等宽分配：长代码与长说明会把首列挤成一条，表格横向溢出。
7. 锚点只写 `href="#p1-1"` 却不给行 `id`（或没有在脚本里补），点击无反应。
8. 打印依赖折叠块却不展开：纸上只剩标题。
9. 每份文档一套配色与版式：团队材料看起来像不同产品。
10. 用 HTML 承载 Markdown 里没有的结论：派生件反过来成为“新事实”。
11. 把含密钥、客户信息或未公开数据的文档做成 HTML 转发。
12. 用圆角卡片、投影与蓝紫渐变：一眼回到通用 AI 报告，和仪器语境无关。
13. 表头做 `text-transform: uppercase`：`JitExpRunnable` 变成 `JITEXPRUNNABLE`，代码标识符不可读。
14. Markdown 标题写“一、二、三”又叠加章节计数器：出现 `04 三、执行阶段` 的双重编号。

## 维护

版本记录在 frontmatter，破坏性改动升 MAJOR；模板与令牌改动要同步更新 `references/layout.md`。真源在本仓：修订先落这里，再同步到各项目副本；下游副本只读，发现问题回填本仓，不要在副本上就地改，否则两份会分叉成互不相容的版本。
