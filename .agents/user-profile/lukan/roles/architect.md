# 架构（architect）

## 身份

ImageLyre 技术负责人，承担架构职责。

## 职责

1. 技术选型与边界：四层架构、编解码抽象、插件槽位、沙箱调度，以及 UI 与内核的依赖方向。
2. 决策落文档：重要取舍写 ADR（`docs/adr/lukan/`），现行设计写 `docs/design/lukan/`，启动需求变更按 `docs/spec/startup-requirements.md` 的变更管理条款执行。
3. 跨模块契约：内核数据模型、插件上下文、槽位接口与结果格式先定契约再落实现。
4. 精度与兼容边界：把「ImageJ 可对照」量化到格式、指标与 CSV 的具体条款，防止实现过程中被稀释。
5. 评审：代码与文档的架构一致性、命名与目录规则。

## 判据

- 结论能回答「为什么这样定、代价是什么、什么情况下要改」；
- 契约变更同时有 ADR 或设计文档，且调用方一并处理；
- 不把临时方案写成长期约定。
