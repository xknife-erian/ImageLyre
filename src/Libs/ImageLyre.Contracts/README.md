# ImageLyre.Contracts：无界面也能工作的服务契约

本工程装的是**离开界面仍然成立**的契约：一个命令行进程或无头宿主把它拿起来就能干活，不需要任何窗口、控件或渲染。判据不是"类型面里有没有控件"，而是"如果没有人看屏幕，这个契约还有没有意义"——按这条判据，命令、快捷键、通知、输出、忙状态、主题、语言、用户习惯、文件对话框与文档页的打开全都不属于这里。

## 分区

分区对应将来的实现模块，一个分区只归一个模块，因此同一处改动不会跨两个工程同步。

| 分区 | 契约 | 文件数 |
| :--- | :--- | :--- |
| `.Documents` | 脏标记与关闭结果、只读感知、选中感知、会话持久化、最近文件、内容标识 | 6 |
| `.Diagnostics` | 诊断服务、崩溃上报 | 2 |
| `.Files` | 外部变更通知 | 1 |
| `.Hosting` | 关闭清理参与者 | 1 |
| `.Messaging` | 事件总线、全局异常处理 | 2 |
| `.Preferences` | 偏好读写、设置项定义与类型 | 2 |
| `.Tasks` | 后台任务管理 | 1 |
| 根 | `IPluginCenter` 插件管理面 | 1 |

根目录下不再放新类型：`IPluginCenter` 是迁入时的遗留位置，归位到 `.Hosting` 之后再增契约一律进分区。

## 放什么，不放什么

放进来的是服务与状态：谁在跑什么任务、哪些文档脏了、偏好存在哪、诊断写到哪里、关停时要通知谁。放不进来的是任何"给用户看或让用户点"的东西，即使它一个控件也不出现——通知中心、输出面板、忙状态、主题切换、文件对话框都属于后者，它们在 `ImageLyre.UI.Contracts` 里。

一个反例值得记住：`ISelectionAware` 描述的是文档内容里的选中范围，属于文档状态，所以留在这里；如果有人把它理解成"选中了哪个控件"，就会错误地迁到界面那本去。

## 依赖

只有一个外部包依赖：`System.Reactive`，理由是契约里的状态变化统一用 `IObservable<T>` 表达，并在注释里写清触发线程、回放语义与是否热流三项。除此之外不引 Avalonia、不引 AtomUI、不引 `Cangming.PicoPlugins`，也不引仓库内任何其它工程。

## 写一条新契约时要做到

1. 流要写三要素：触发线程、订阅后是否回放当前值、是热流还是冷流；缺一项，订阅方就会各自猜线程。
2. 注册与订阅要能撤销：凡挂上去的东西都返回 `IDisposable` 或受所有者作用域管辖，因为插件停用之后残留的订阅会继续改界面，是"幽灵行为"最常见来源。
3. 命令可用性用委托谓词表达，不用 `When` 字符串表达式；字符串表达式需要一门自造语法与求值器，而我们的命令数量与条件复杂度都不值得。
4. 不写成熟度标注：本仓契约只有一个实现方，实验与稳定之间没有判定人与转换机制，标注会全部停在实验级，成为一条恒为真的注释。
5. 值对象用 `record`，集合暴露 `IReadOnlyList<T>` 或只读快照，不给调用方留改写内部状态的入口。

## 常见错误

| 症状 | 后果 |
| :--- | :--- |
| 契约里出现 `Control`、`ResourceDictionary`、`Window` | 纯服务模块被迫拖着界面框架启动 |
| 契约引用实现工程 | 依赖成环，实现无法被替换与停用 |
| 用 `event` 加"内容变了去重读"的粗粒度通知 | 订阅方每次全量重读，绑定到界面上就是整树重建 |
| 给"以后可能要"的扩展预留空接口 | 抽象过早，等需求真来了还得改形状，两次成本 |
